Attachments

Drop files onto the window, paste them, or pick them from the + menu next to the message box. Loach reads each file on your machine and adds its contents to your message - there is no separate upload step, and nothing leaves your machine unless you are using a cloud provider.

Adding files

  • + menu - Add files opens the native file picker; pick as many files as you like. Ctrl + U opens the same picker.
  • Drag and drop - drop files anywhere in the window while a message box is on screen. The box reads Drop files here to attach while you drag.
  • Paste - Ctrl + V in the message box attaches any files on the clipboard, such as a screenshot or files copied in your file manager. Plain text pastes as text.

Each file becomes a chip above the input, after any persona and tone chips. Click a chip’s × to drop it before sending. You can send files without typing anything; the chips leave with the message.

The same menu’s Add directory item (Change directory once the chat has a folder) does something different: instead of copying files into one message, it lets the model list, read and edit the files in a folder for the rest of the chat. It becomes available once the chat has its first message. See Work in folders.

Supported file types

Loach sorts every file into one of four kinds:

  • Images - PNG, JPEG, WEBP and GIF. Sent to the model as images alongside your text, so they need a vision-capable model.
  • Text and code - about seventy recognised extensions (Python, TypeScript, Rust, Go, JSON, YAML, Markdown, CSV, SQL, shell scripts, Dockerfile, Makefile and so on) plus anything with a text/* type. The file is read as UTF-8 text and added verbatim inside a code block.
  • Documents - PDF and DOCX. Loach extracts the plain text and adds that; a PDF is read page by page, each page under a “Page N” header. Layout, formatting and embedded images are lost. A scanned PDF with no text layer has nothing to extract, and the model is told so.
  • Everything else - legacy .doc, archives, binaries and other image formats such as BMP, TIFF, HEIC or SVG. These attach, but Loach can’t read them; see below.

How attachments enter the prompt

When you send, your typed prompt comes first, followed by one block per text file or document, in the order you added them. Each block opens with a header naming the file (“Attached file”, “Attached PDF” or “Attached Word document”), so the model knows what it is looking at. Pages pulled in by web fetch come after the attachments.

Your bubble in the transcript shows only what you typed, with the files as chips, but the extracted text is stored with the message. It is sent again with the chat history on every later turn and counts toward the context window - the context usage popover lists it as of which attachments.

Images work differently: they reach the model only with the message they are attached to, and again if you regenerate that reply. Later turns don’t resend them, so attach the image again if you want the model to take another look.

Caps and truncation

To keep the prompt manageable, Loach applies three limits:

  • 20 MB per file - a bigger file is refused, with “name is larger than 20 MB.” under the message box.
  • 200,000 characters per file - a longer text file, PDF or DOCX keeps only its first 200,000 characters. Its chip in the message box gets an amber truncated pill, and a note at the cut tells the model what was left out (for a PDF, how many of its pages it got).
  • 500,000 characters per message - counted across your prompt, every attachment and any fetched pages. Earlier attachments win: one that only partly fits is clipped with a note to the model, and files with no room left are listed by name in a short footer, so the model knows they exist and can ask you for an excerpt. Neither case shows a pill on the chip.
Tip

For very large documents, paste the section you actually want reasoned about instead of dropping the whole file. The model gets cleaner context and you burn fewer tokens.

Files Loach cannot decode

Legacy .doc files, archives, binaries, unsupported image formats and anything else Loach does not parse still attach. The file is kept with the message and the model is told its name, but none of its content. The model can still acknowledge that “you attached report.zip” and ask for a usable version, and you can open the chip and Save the file back out.

Previews

Click a chip - in the message box or on a sent message - to preview it without leaving the chat. This covers files you attached, images returned by MCP tools and PDFs produced by the built-in pdf tool alike. Loach picks the viewer based on what the file is:

  • Images - open in a lightbox with a Save button. Click the dim backdrop or the × to close.
  • PDFs - open as a scrollable preview that renders each page as you reach it, with Save writing the original file. This needs the PDF’s original bytes, which Loach keeps for a PDF still in the message box and for PDFs from the pdf tool - not for a PDF you have already sent in a regular chat.
  • Text and code - open in the code canvas under the file’s name, with highlighting, and with Export defaulting to the original file name.
  • Everything else - DOCX files, files Loach can’t decode, sent PDFs and any PDF that fails to render open a card reading Preview not available, with a Save button so you can still pull the file back out. For a PDF or DOCX that has already been sent, Save writes the extracted text as a .txt file, so keep your original.
In Private Chat

Private Chat takes files from its own + button only. Dropping files is refused while it is open, so nothing lands in the regular chat behind it, and pasting a file doesn’t attach it. Text and code chips open the file card instead of the canvas, and files on sent messages show as plain name labels.
