Storage & privacy

Loach is local-first. Your content lives on your machine, and nothing goes over the network unless you set up something that needs it - a remote provider, web fetch, an MCP server, the update check. Here’s exactly what is stored, where, and what leaves your machine and when.

Where things live

WhatWhere
Chats and messages (with their tool calls and results), folders, labels, pinned responses, Spaces with their sources and memories, global memories, Snippets with their variables and saved fill-ins, MCP servers, app settingsSQLite at <app-data-dir>/loach.db, plus its -wal and -shm files
Attached filesInside their message in loach.db - images and other files as base64, text and documents as their extracted text. There is no separate file store.
OpenAI-compatible API keyOS credential manager (Windows Credential Manager / Linux Secret Service / macOS Keychain)
App-lock hash + hintOS credential manager - same store, separate entry
MCP server headers and environment variablesIn loach.db as plain text, with the rest of the server’s settings - not in the credential manager
A chat’s working folderOnly its path, on the chat. The files stay where they are; Loach doesn’t copy them.
Code-canvas snippets opened in VS CodeScratch files in <app-cache-dir>/canvas
Layout preferences (canvas width, open sidebar folders, the parameters panel’s view)The app window’s local storage
Local modelsStored by Ollama, outside Loach’s folders
App data dir on Windows%APPDATA%\dev.loach.app\
App data dir on Linux~/.local/share/dev.loach.app/
App data dir on macOS~/Library/Application Support/dev.loach.app/
App cache dir%LOCALAPPDATA%\dev.loach.app\ on Windows, ~/.cache/dev.loach.app/ on Linux, ~/Library/Caches/dev.loach.app/ on macOS

The database isn’t encrypted: anyone who can read your app-data folder can read your chats, and any MCP credentials stored with your servers. Loach writes no log files.

Offline by default

With a local Ollama, Loach launches and works completely offline. All of these need no network access:

  • The Models library
  • Spaces, Snippets and memory
  • Search across chats, messages, Spaces and Snippets
  • The parameters panel
  • The app lock
  • Full chat history, and Private Chat
  • Built-in tools, working folders and LaTeX math rendering - KaTeX ships inside the app

Only chats with a remote endpoint (OpenAI, Groq, OpenRouter, …), web fetch, remote MCP servers, the update check and model downloads need an internet connection. An Ollama or OpenAI-compatible server elsewhere on your network needs that network, not the internet.

No telemetry

Loach does not phone home. There is no account, no usage tracking, no analytics, no crash reporting service. The app window itself can’t reach the internet: its content security policy allows no remote scripts, images or connections, and no inline scripts or eval, so every request goes through Loach’s backend - and only for the reasons below. Nothing else happens in the background.

What goes over the network, and when

DestinationWhen
Your Ollama base URL (http://localhost:11434 by default)At launch, to see whether Ollama is running and list its models; then for every chat, model preload and Models-tab action. Pulling a model makes Ollama download it from its library - that connection is Ollama’s, not Loach’s.
Your OpenAI-compatible endpointIts model list at launch and when the provider settings change - but only once you’ve saved an API key or pointed the base URL away from the OpenAI default. Then every chat you run on it, and Test connection.
URLs in your promptOnly with Web fetch switched on (it’s off by default), plus a page you fetch with /fetch. Addresses on your own machine or private network are refused.
Your MCP serversAn HTTP server whenever a chat needs its tool list or calls one of its tools. A local (stdio) server is a program on your machine; what it connects to is up to that program.
GitHub releasesWhen you press Check for updates in Settings → Updates, or once per launch if you switched on Auto-check for updates (off by default). An update is downloaded only when you confirm.
Your web browserLinks you click in a reply, the model-library links in onboarding and the share buttons open in your default browser, which makes those requests itself.

What a remote provider receives

A chat on a remote endpoint sends that provider everything the model needs for the turn:

  • The system prompt - the instructions that apply (the Space’s, the chat’s or your Custom instructions), the persona and tone, the date, weekday and timezone while Temporal awareness is on, your name wherever {{USER_NAME}} appears, a Space’s reference sources, and your memories.
  • The conversation - your messages and its replies (a compacted chat sends its summary instead of the older turns), with attachments inlined and the text of any pages Web fetch downloaded.
  • Tools - the definitions of the tools that are on, and every tool result: what MCP servers return, and the contents of files the model reads from the chat’s working folder. The folder’s full path and its LOACHFILE.md go in the system prompt.

Two background requests go to the same provider and model: memory extraction after each reply while Space memory or global memories are on, and the summary when you compact a chat. Global memories are sent with every chat, whichever provider it uses - a fact learned talking to a local model also reaches a cloud one. Private Chat talks to Ollama only and never uses memory.

The API key is sent only over https://, or over http:// to this computer (localhost, 127.0.0.1, ::1). An http:// server elsewhere on your network gets no key.

Secrets handling

The API key and the app-lock credentials are stored in your operating system’s credential manager via the keyring crate, under the service name dev.loach.app:

  • On Windows - the Credential Manager.
  • On Linux - the Secret Service (GNOME Keyring / KWallet / equivalent). One has to be running and unlocked, or the key won’t save.
  • On macOS - the Keychain.

The key never reaches the database or the app window, and Settings never shows it back. App-lock secrets are hashed with Argon2id before they’re stored; the plaintext is never written anywhere. The optional lock hint is stored as you typed it, in the same entry, because the lock screen shows it.

MCP credentials are the exception: a server’s HTTP headers (an Authorization token, say) and a local server’s environment variables are kept in loach.db as plain text. Exports leave them out.

Files and programs

  • File access goes through Loach’s backend. Saving an export or an attachment, importing a backup and picking a working folder all use native dialogs, and the backend does the reading and writing, so the app window can’t read or overwrite a file you didn’t pick.
  • Working folders are sandboxed. The model reaches only the files inside the folder you picked for a chat - absolute paths, .. and links pointing elsewhere are refused, a whole drive and Loach’s own data folder can’t be picked, and there is no shell. Before a file is written, edited, moved or deleted, Loach shows you the change and asks, unless you’ve allowed that tool for the chat. See Work in folders.
  • Local MCP servers need your consent. Testing, switching on or changing a local (stdio) MCP server raises a native system dialog that shows exactly what will run, with Cancel as the default button. Imported local servers arrive switched off.
  • MCP tool calls ask first. By default every call pauses the reply and shows the server, the tool and its arguments: Allow once, Always allow that tool, or Deny. Turn Ask before each tool call off only for a server you trust. See MCP support.

Backup, restore and wipe

From Settings → Data you can:

  • Export data - save your full content (chats, folders, Spaces with their sources and memories, global memories, Snippets and variables, MCP servers, settings) to a single JSON file. MCP headers and environment variables are left out, and so are secrets in a server’s arguments (a password in a URL, a --token value); chats leave out their working folder.
  • Import data - restore a previously exported file. It replaces everything in the database but keeps the stored API key. Local MCP servers come in switched off.
  • Erase & Reset → Remove my data - delete chats, folders, Spaces, memories, Snippets and MCP servers, but keep settings, the API key and the app lock.
  • Erase & Reset → Factory reset - the same, plus all settings, and remove the API key and the app lock from the credential store. Loach then starts over with onboarding.

Both erase options ask you to type YES; importing and erasing also ask for your current app-lock credentials when a lock is set. A storage breakdown above those controls shows what chats, attachments, Spaces and everything else weigh in the database, and what your local Ollama models take on disk. The API key and the app lock are never part of an export - they live in the OS credential manager and stay there until you remove them. See Data management.
